# 段階 4 の依頼者の確認とインストールの体験の結果

## はじめに

段階 4 でドック、設定画面、ホットキー、テキストソースへの表示を実装したあと、依頼者が 2026-11-10 に OBS で確認し、開発用の配置と設定を消した状態から初回の設定を体験しました。この報告は、確認の結果と依頼者の所見、所見への対応をまとめたものです。手順書は `.prompts/MANUALS/2026-11-10-stage4-dock-check.md` と `.prompts/MANUALS/2026-11-10-stage4-install-experience.md` です。

## 検証方法

- 前半: ドックから開始と停止をし、動作中のまま OBS を閉じた。Claude Code がシーンコレクションの JSON で表示先の text の長さを確かめた
- 後半: 無効なキーでの開始、正しいキーでの再開、ホットキー
- インストールの体験: Claude Code がプラグインのフォルダー、設定フォルダー、シーンコレクションのこのプラグインのキーを消し、リリースの ZIP と同じ構成のフォルダーを配置した。インストールは依頼者の依頼で Claude Code が行い、依頼者は初回の設定から体験した

## 検証結果

| 確認 | 結果 | 根拠 |
| --- | --- | --- |
| 開始と停止、3 つの表示 | 合格 | 依頼者の目視 |
| 動作中に閉じたあとのシーンコレクション | 合格 | scenes.json の表示先 3 つの text の長さが 0。scenes.json.bak には text の設定が無い |
| 選択の復元 | 合格 | 依頼者の目視 |
| 無効なキー | 初回は不合格、修正後に合格 | 初回は「設定を受け付けませんでした」と表示。修正後の OBS のログ 2026-11-10 20-26-19.txt で invalid_api_key により停止し、依頼者が認証の失敗の表示を確認 |
| 正しいキーでの英訳と概要 | 合格 | 同じログで英訳と概要がすべて HTTP 200 |
| ホットキー | 合格 | 依頼者の目視。修正後は切り替えのホットキーで確認 |
| 終了 | 合格 | 同じログに Number of memory leaks: 0 |

無効なキーの初回の不合格の原因は、OpenAI が無効なキーでも WebSocket のハンドシェイクを HTTP 101 で通し、error イベント (error_code=invalid_api_key) を送ってから終了コード 3000 で閉じることでした。実装は 401 だけを認証の失敗として扱っていました。

## 依頼者の所見と対応

| 所見 | 対応 |
| --- | --- |
| 既定が空だと、開始を押すまでテキストソースの位置を調整できない | 停止中は表示先に出力ごとの仮の文字列を出す。設定画面のチェックで切り替えられ、既定はオン (依頼者が A 案を選んだ) |
| プラグインは無料だが、OpenAI API の利用料金は利用者の負担であることを明記すべき | 設定画面の API キーの欄に注記した。README と倉庫くんの説明文には段階 6 で書く |
| 「固有名詞のヒント」が何のことか、エンドユーザーには分からない | 画面の名前を「聞き取ってほしい言葉」に変え、欄の下に用途の説明を置いた |
| 開始と停止を同じキーで切り替えられないと不便 | 開始/停止の切り替えのホットキーを足した。開始と停止のホットキーも残した |

## 考察

所見はいずれも、仕様書の段階では見えていなかった利用者の立場の不便さでした。実際に操作して初めて分かる点が多く、段階 5.5 のユーザーテストでも同じ観点の確認が有効だと考えています。
