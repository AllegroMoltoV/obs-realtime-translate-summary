# 英訳と概要のモデルの比較

## はじめに

INIT.md 11.2 節の仮決め (英訳と概要に gpt-6-luna を使い、reasoning.effort を none にする) を確定させるため、gpt-6-luna と次の候補の gpt-5.6-luna、gpt-5.4-nano を同じ入力で比べました。比較は 2026-11-10 に行いました。

## 検証方法

- 道具: `tools/model-eval/main.cpp`。OBS を使わずに Responses API を呼ぶ。指示文、スキーマ、概要の検証はプラグインと同じ `src/core/` を使う
- 入力: `tools/model-eval/samples/` の架空の一人語り。ピアノの練習、週末の予定の雑談、プラグインの作業の 3 つの場面で各 20 発話。フィラー、言い直し、文の断片を含む
- 英訳は全 60 発話、概要は最短間隔 10 秒と直近 5 分の窓の規則で 53 回、各モデルで呼んだ。同じ入力を 3 つのモデルへ交互に送った
- 概要の 1 行の最大文字数 N は既定の 30。指示文が求める上限は N-2 の 28 文字
- 生成した全文は `docs/logs/2026-11-10-model-eval/outputs.md`、集計は同じフォルダーの `stats.md`

## 検証結果

3 つのモデルとも reasoning.effort の none と temperature を受け付け、失敗は 0 件、推論のトークンは 0 でした。

| --- | --- | --- | --- | --- | ---: |
| gpt-6-luna | 1,265.2 / 1,916.4 ms | 1,941.9 / 2,792.5 ms | 引用符 1 | 57 行 | 0.012 米ドル |

| 元のツール (Gemini) の実績 | 844.1 / 1,268.4 ms | 1,176.2 / 1,817.3 ms | | | |

英訳の引用符の違反は、2 つのモデルとも曲名を “Clair de Lune.” のように引用符で囲んだ 1 件です。訳文の全体を囲んだものではありません。

`outputs.md` を読んで確認した概要の傾向は次のとおりです。

- gpt-6-luna: 発言の対象と動作を具体的に残し、時制も保っていました。ただし 28 文字を超える行が多く、最長は 49 文字でした。画面では 29 文字と … に切り詰められます
- gpt-5.6-luna: ほぼすべての行が上限内でしたが、多くの行が 13 から 18 文字で、指示文の目安の 24 文字より短く、情報が落ちていました。また、伏見稲荷、清水寺、銀閣寺を「三寺」と書いた行と、「伏見稲荷など三か所」と「など」で省略した行がありました。前者は発言と異なる記述、後者は指示文が禁じる省略です
- gpt-5.4-nano: 新しい発言を優先せず、「今日は雑談枠で、特に決めてないです。」のような冒頭の発言を最後まで残し続けました。28 文字の超過も多くありました

### 追加の比較: 概要の reasoning.effort low

gpt-6-luna と gpt-5.6-luna の概要だけを、reasoning.effort low で同じ 53 回呼びました。公式のガイドにしたがい temperature は送っていません。生成した全文と集計は `docs/logs/2026-11-10-model-eval-low/` にあります。

| モデル | 失敗 | 不正な応答 | 28 文字の超過 | 中央値 / p95 | 平均の推論のトークン |
| --- | ---: | ---: | ---: | --- | ---: |
| gpt-6-luna | 25 | 6 | 10 行 | 5,161.3 / 6,694.6 ms | 374.1 |
| gpt-5.6-luna | 21 | 3 | 2 行 | 1,716.9 / 5,034.7 ms | 289.9 |

失敗は HTTP 200 で本文が空の応答です。max_output_tokens の 512 は推論のトークンを含むため、推論で上限を使い切ったと推測します。

### 英訳の内容

`outputs.md` の英訳を読み比べた範囲では、gpt-6-luna と gpt-5.6-luna の訳の質に大きな差は見られませんでした。gpt-5.4-nano は「今日はここまでで30分くらいなので」を「We’ll stop here for about 30 minutes today」と誤訳し、ドビュッシーの月の光を moonlight sonata と訳していました。固有名詞の「倉庫くん」は、3 つのモデルとも正しく訳せませんでした。

## 考察

11.2 節の確定の条件に照らすと、3 つのモデルとも条件をすべては満たさないと考えています。

- 概要の条件 (発言にない内容を加えない、時制を保つ、N-2 文字の上限を守る) について、gpt-6-luna は上限を守れず、gpt-5.6-luna は発言と異なる記述と禁じた省略を含みました
- 処理時間の条件について、英訳の中央値は 3 つのモデルとも元のツールの 844.1 ms に届きませんでした。概要の p95 は gpt-5.6-luna だけが元のツールの値以下でした
- 費用の差は 1 時間あたり最大 0.014 米ドルで、文字起こしの費用の約 0.041 米ドルに比べて小さく、判断を左右しないと考えています

gpt-5.4-nano は新しい発言を優先しない点が概要の目的に反するため、候補から外すのが妥当だと考えています。

reasoning.effort low は、処理時間が数秒に伸び、失敗も増えるため、配信の字幕と概要には使えないと考えています。

概要の内容の正確さは gpt-6-luna が最も良く、問題は行の長さに集中しています。行が長すぎる場合は元のツールと同じく … で切り詰めるため、表示が崩れることはありません。利用者は設定で 1 行の最大文字数を増やせます。一方、gpt-5.6-luna の概要は発言と異なる記述を含むことがあり、11.2 節の、発言にない内容を加えない、という条件により深く反すると考えています。

英訳は gpt-6-luna と gpt-5.6-luna で質の差が小さく、gpt-5.6-luna のほうが中央値で約 190 ms、p95 で約 400 ms 速いです。そのため、英訳に gpt-5.6-luna、概要に gpt-6-luna を使い、どちらも reasoning.effort none とする組み合わせが、正確さと速さの両方で最も良いと考えています。
